# Phased Implementation Plan

Each phase ends with a working app, passing checks, and a Git commit or pull request. Later phases are not started until the earlier one has been reviewed.

**Development strategy (from 7 Oct 2026): iOS-first prototype.** Native alarms are already proven on a physical iPhone and Android phone. New features are built and tested on iOS first, with shared logic in platform-neutral TypeScript and native behaviour behind service interfaces (like `AlarmService`). Android code already written is kept, and shared logic stays platform-neutral, but new native features aren't duplicated in Kotlin until the behaviour is validated. **Updated 11 Oct 2026:** to prioritise speed, phases no longer end with an Android build check. Android compatibility, native compilation, physical testing and full feature parity are deferred to the dedicated **Android parity phase (A)**, after the iOS prototype is feature-complete. Basic Android native alarms were already proven on a physical phone in Phase 1.
